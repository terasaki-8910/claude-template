# 作る前に確認する（確認シート）

ユーザーが決めることは、見えるもので確かめてから作る。確かめるときは、本物の見本を載せた確認シートを1枚にまとめて出し、回答はシートから自分で読む。

## いつも守ること

- 次のことはユーザーが決める。自分で決めない。
  - 依頼がいくつにも読めるときの、どの意味か
  - ユーザーが目にするもの（配置・見た目・文言）
  - 作る範囲
  - はっきりした正解がないトレードオフ
  - 指示どうしの食い違い
- これらは、理解したことを見えるもの（本物の見本を載せた確認シート、または手元で開けるテストページ）で示して「こういうことでしょうか」と確かめ、ユーザーが GO と言ってから作る。指示書が完成して見えても、それは GO ではない。
- 確認は、判断の節目ごとに1枚のシートにまとめる。その時点で決まっていないことを全部載せる：受け入れ待ちの結果、次の作業の見本、案つきの文言、作業の外で見つけたこと、作ったあとの扱い（「確かめが通ったら main に取り込むか」など）。
- 質問は、どの組み合わせで答えても成り立つように作る。次の回に回すのは、作ってみないと答えられない質問だけ。
- テストで決まること、決まったやり方があること、簡単に戻せることは聞かない。自分で決めて1行で伝える（シートがあれば「聞かずに決めたこと」に載せる）。
- 見るものが無い短い質問が1つだけなら、シートを作らずにその場で聞いてよい。
- 作業の外で見つけた不具合や改善は、黙って直さず、シートに載せる。
- プロジェクトに決定記録があれば、指示書やメモリより優先する。決定記録に無いことは、まだ決まっていない。決定記録が無く、作業が何回にもまたがるなら、どこに置くかを聞く。

## シートの作り方

### 1. 質問を集める
- 決定記録と指示書を先に読む。決まっていることは聞き直さない。食い違いは、それ自体を質問にする。
- 質問は、答えによってやることが変わるものだけにする。変わらないなら自分で決め、「聞かずに決めたこと」に載せる（あとで覆せるように）。
- 質問どうしの依存は、質問の中に書く（「R2-3 で B のときは…」）。

### 2. 見本は本物にする
- 説明ではなく、見せる。作れるものは実際に作り（git worktree で。main には入れない）、出力を見せる。画面ならスクリーンショット、コードやデータなら実際の入力に対する実際の出力、文言なら表示される場所に入れた状態。作るのが割に合わないときだけモックにし、モックだと書く。
- 画面は、スマホ（390px）と PC（1280px）、ライトとダークで確かめる。違いが出ようのない変更は除く。
- 公開する前に、見本をスクリプトで確かめる（スクリーンショットと、DOM・位置・ピクセルの判定）。間違った見本は、ユーザーの1回分の時間を無駄にする。
- スクリーンショットの近くに、動いている見本と今の版の場所（手元の URL、ブランチ名）を書き、並べて開けるようにする。

### 3. シートを組む
- 雛形 `docs/decision-sheet-template.html`（プロジェクトに無ければ `~/.claude/decision-sheet-template.html`）から作り、Artifact ツールで公開する（ツール自身の手順に従う）。ページは `db` を宣言する。
- すべてユーザーの言語で書く。ユーザーや仕様の言葉は、言い換えずにそのまま引く。
- 冒頭：この回で扱うこと、作業の状態（未コミット・ブランチ・公開済み）、質問の数、保存の状態の表示。
- 質問ごと：番号（R<回>-<番号>）、1〜2文の背景、2〜4個の選択肢を見本つきで並べる（押すと拡大）。おすすめを先頭に置き、理由を1行添える。どの質問にも自由記入欄を付け、選択肢を選ばずに書いたときは「その他」として扱う。答えが集合のときは複数選択にする。
- 最後に「そのほか」の欄と、送り方を置く。
- ライトとダークで読めて、スマホの幅とキーボードで使えること。
- 回答の保存：回ごとに1件、`answers/round<N>` に `{ <質問の番号>: { choice, note }, updatedAt }` で入れる。`choice` は選択肢の値（複数選択なら配列）、`"other"`、または null。変えるたびに自動で保存し（700ms ほど待ってから）、開いたときは保存済みの回答を戻し、保存の状態を出す。
- 保存できないとき（Artifact ツールが無く、手元のサーバーで開く場合も）のために、回答を文章にしてコピーするボタンを付ける。
- シートはプロジェクトに1つにし、回ごとに同じファイルから公開し直す。リンクが変わらず、前の回の回答も残る。
- チャットには、リンクと質問の数だけを書く。

### 4. 回答を受け取ったら
- `answers/round<N>` を自分で読む（ArtifactData）。貼り付けは頼まない。待っている間にチャットで言われたことも合わせ、シートとチャットが食い違えば聞く。
- 決まったことを短く並べて返す。聞き直すのは、あいまいな補足と食い違いだけ。
- 回答を、日付つきの見出しの下に、ユーザーの言葉のまま決定記録に追記する。後の見出しが前の見出しより優先する。
- GO が出たものだけを作る。機械的な確かめ（テスト・lint・スクリーンショットの比較）を通し、結果は次のシートで受け入れてもらう。
